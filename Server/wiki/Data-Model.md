# Data Model

Parley uses MongoDB through Mongoose. MongoDB references are stored as
ObjectIds.

## User

Collection/model: `User`

| Field | Type | Notes |
| --- | --- | --- |
| `username` | String | Required; unique |
| `email` | String | Required; unique |
| `password` | String | Required; stored as a hash |
| `Avatar` | String | Defaults to an empty string |
| `createdAt` | Date | Defaults to the current time |
| `updatedAt` | Date | Defaults to the current time |

Unique indexes exist on `username` and `email`.

## Session

Collection/model: `Session`

| Field | Type | Notes |
| --- | --- | --- |
| `sessionId` | String | Required; sent in the cookie |
| `userId` | ObjectId | Required reference to `User` |
| `expiresAt` | Date | Required; login sessions last 24 hours |

`requireAuth` searches by `sessionId` and rejects sessions whose
`expiresAt` is in the past.

## Room

Collection/model: `Room`

| Field | Type | Notes |
| --- | --- | --- |
| `name` | String | Defaults to an empty string; used by groups |
| `type` | String | Required; `group` or `direct` |
| `directKey` | String | Used to deduplicate direct rooms |

`directKey` has a unique partial index for string values. It is generated by
sorting the two member IDs and joining them with `:`.

## Membership

Collection/model: `MemberShip`

| Field | Type | Notes |
| --- | --- | --- |
| `room` | ObjectId | Required reference to `Room` |
| `user` | ObjectId | Required reference to `User` |
| `role` | String | `owner`, `admin`, or `member`; defaults to `member` |
| `joinedAt` | Date | Defaults to the current time |
| `lastReadAt` | Date | Defaults to the current time |

A unique compound index on `{ room, user }` prevents duplicate membership.
There is also an index on `user` for room listing.

## Message

Collection/model: `Message`

| Field | Type | Notes |
| --- | --- | --- |
| `message` | String | Required message text |
| `room` | ObjectId | Required reference to `Room` |
| `sender` | ObjectId | Required reference to `User` |
| `createdAt` | Date | Automatically created |

Messages have indexes on `room` and `sender`. Room history queries sort by
`createdAt` descending.

## Relationships

```text
User 1 ──── * Session
User 1 ──── * Membership * ──── 1 Room
User 1 ──── * Message    * ──── 1 Room
```

Membership connects users to rooms. Messages refer to both their room and
sender. The current services do not populate full room/member/message
relationships in every response; clients should use the IDs returned by the
API.
